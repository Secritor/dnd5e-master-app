# dnd-game-tool

Фронтенд-SPA для D&D: React 19 + Vite 7, архитектура Feature-Sliced Design.
Бэкенда нет — данные mock (статические массивы + искусственная задержка). Деплой — статика на GitHub Pages.

## Команды

| Команда | Назначение |
|---|---|
| `npm run dev` | дев-сервер (Vite, `--host`) |
| `npm run build` | `tsc -b` + `vite build` — **главная проверка перед завершением задачи** (отдельного typecheck/тестов нет) |
| `npm run lint` | ESLint |
| `npm run lint:fsd` | Steiger — границы FSD |

Показывай результат проверки (вывод команды), а не утверждай «готово» без него.

## Карта проекта

**Перед поиском по коду сверяйся с [documents/project-structure.md](documents/project-structure.md).**
Там: дерево файлов с аннотациями, слои FSD, таблица роутов, карта состояния (Zustand-сторы + TanStack Query), граф зависимостей слайсов и таблица «где что менять». Свериться с картой дешевле по токенам, чем сканировать репозиторий.

**После изменений, меняющих структуру, обнови `documents/project-structure.md` в том же коммите.**
Структурные изменения = новый слайс / страница / роут / стор / зависимость, перемещение файлов, смена UI-кита или системы стилей, изменение дерева провайдеров. Если структура не поменялась — файл не трогай.

## Контекст и токены

Контекстное окно — главный ограниченный ресурс: качество ответов падает по мере его заполнения. Цель — наименьший набор высокосигнальных токенов, достаточный для задачи (во входе и в ответах).

- **Just-in-time, а не заранее.** Не читай файлы «на всякий случай». Держи пути/идентификаторы и подгружай содержимое, когда оно действительно нужно.
- **Точечное чтение.** Для крупных файлов — `offset`/`limit` или Grep с контекстом вместо чтения целиком. Не читай директории пачкой.
- **Поиск — через Grep/Glob**, а не `cat`/`find`/`ls -R` в Bash.
- **Вывод команд — фильтруй** (`| tail -n`, флаги тихого режима). Не заливай полные логи сборки/установки в контекст.
- **Не дублируй уже известное.** Не перечитывай только что отредактированный файл; не пересказывай то, что уже сказано в диалоге; не перечисляй варианты, которые не выбрал.
- **Крупное исследование — в изоляции.** Обход многих файлов, широкий разведочный поиск, «изучи, как устроено X» → отдельный субагент, возвращающий сводку на 1–2k токенов (когда пользователь просит делегирование), либо предложи `/clear` между несвязанными задачами.
- **При компактификации сохраняй:** список изменённых файлов, архитектурные решения, незакрытые баги, команды проверки.

## Стиль и гочи

- Тема жёстко тёмная (`<html class="dark">`), переключателя светлой нет.
- Новый UI — CSS Modules + токены из `src/app/styles/tokens.css`; Tailwind-утилиты только в `shared/ui` (легаси, не расширять).
- UI-компоненты бери из `@/shared/ui` (реэкспорт HeroUI v3), а не из `@heroui/react` напрямую по экранам.
- Любая строка интерфейса — сразу в оба локаля: `src/shared/config/locales/ru.ts` и `en.ts` (ключи типизированы, файлы держим синхронными).
- `components.json` (shadcn) и папка `dist/` — мёртвый легаси, не опираться на них.
