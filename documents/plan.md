## 1. Что уже сделано

### Инфраструктура (готово, менять не планируется)

- React 19 + Vite 7, TypeScript strict, архитектура FSD v2.1 (линт — Steiger).
- Хеш-роутер (`createHashRouter`), все страницы через `lazy()` + `Suspense` + `ErrorBoundary`.
- TanStack Query (server state), Zustand (client state, `persist` для кампаний мастера).
- Формы: react-hook-form + Zod.
- i18n: i18next, локали `ru` (дефолт) / `en`, ключи типизированы.
- Тема жёстко тёмная, UI-кит HeroUI v3 через `@/shared/ui`, стили — CSS Modules + токены.
- Данных с бэкенда нет: моки = статические массивы + искусственная задержка.
- Мониторинг: `@vercel/speed-insights`.

### Экраны (черновики / каркасы)

| Роут | Состояние | Что есть сейчас |
|---|---|---|
| `/` — выбор режима | каркас, UI под замену | 3 кнопки: Игрок → `/player`, Мастер → модалка входа, Компании → `/company` |
| Модалка входа мастера | мок, без реальной логики | `login / register / success`, Zod-валидация форм, при «успехе» → `navigate('/master')`. Реальной аутентификации нет |
| `/master` — пространство мастера | почти пусто, UI под замену | заголовок, список кампаний из Zustand + форма создания, сайдбар со ссылками на архивы |
| `/company` — каталог кампаний | рабочий черновик | 20 официальных кампаний (мок), фильтры: поиск / настроение / уровни; карточки + скелетоны |
| `/master/spells` — заклинания | заглушка с таблицей | TanStack Table, 4 мок-записи |
| `/master/npcs` — NPC | заглушка «в разработке» | данных нет |
| `/player` — режим игрока | заглушка «в разработке» | — |

### Легаси в репозитории (учитывать, не опираться)

- `pages/master-auth/` — нероутовая страница-версия входа, не подключена (вход идёт через модалку).
- `components.json`, папка `dist/` — мёртвый след shadcn / до-FSD структуры.

## 2. Целевая UX-логика (как задумано)

- **Стартовый экран `/`** — выбор роли: **Игрок / Мастер**. Редизайн: две кнопки в колонку (сейчас три в ряд). Кнопка «Компании» уходит со стартового экрана — вход в каталог переезжает в пространство мастера.
- **Вход мастера** — через модалку, после входа переход в пространство мастера.
- **Пространство мастера (`/master`)** — хаб с четырьмя разделами, у каждого своя страница:
  1. **Компании** — официальные кампании (сейчас `/company`, переезжает под хаб).
  2. **Заклинания** — архив заклинаний и умений.
  3. **NPC** — база NPC мастера.
  4. **Предметы** — база предметов / снаряжения (нового кода пока нет).
- Навигация: хаб → раздел → назад в хаб (кнопка «Назад» уже есть в `shared/ui/page-title`).
- **Макет `/master` не определён.** Конкретный UI хаба пока неизвестен — на Этапе 1 нужно сделать приблизительный ui-макет компоновки четырёх разделов (см. §4).

### Что из этого расходится с текущим кодом

- «Компании» сейчас открываются со стартового экрана — вход в раздел переносится в пространство мастера; сам роут можно оставить (`/company`) или вложить в `/master/company`.
- `/master/npcs` и `/master/spells` уже вложены в `/master` — структура под цель подходит, надо наполнить.
- Раздела «Предметы» нет вообще — новый слайс `pages/*`.
- Стартовый экран `/` и `/master` — оба под редизайн.

## 3. Открытые вопросы (требуют решения до реализации)

### 3.1. Аутентификация — как без бэкенда

Проект — статика на GitHub Pages, отдельного сервера нет. Варианты:

| Подход | Плюсы | Минусы | Когда подходит |
|---|---|---|---|
| **Мок в localStorage** (Zustand `persist`) | 0 инфраструктуры, быстро, остаёмся чистой статикой | не защищает ничего, данные только на одном устройстве | демо, портфолио, пока логика приложения важнее «настоящего» входа |
| **Supabase Auth** (клиентский SDK) | email+пароль и OAuth, БД в комплекте, щедрый free tier, фронт остаётся статикой | внешний сервис, ключи в бандле (нужен RLS на стороне Supabase), вендор-лок | если нужен реальный аккаунт + синхронизация данных между устройствами |
| **Firebase Auth** | то же, что Supabase; очень зрелый Auth | экосистема Google, конфиг в бандле | альтернатива Supabase |
| **Clerk / Auth0** | готовый UI входа, минимум кода | SaaS-зависимость, лимиты free tier | если не хочется верстать формы входа |

**Рекомендация для старта:** мок в localStorage (роль + «сессия»), с изоляцией всей логики в `features/master-auth/model` — чтобы позже подменить на Supabase, не трогая экраны. Решение зафиксировать здесь.

## 5. Технический долг

Из [project-structure.md §9](project-structure.md) и осмотра репозитория:

- **Деплой рассинхронизирован:** `vite.config.ts` → `build.outDir: 'docs'`, а `.github/workflows/deploy.yml` публикует `./dist`. Сейчас CI выкладывает **устаревшую** папку `dist/`, а не свежий билд. `.gitignore` игнорирует `dist`, но не `docs`.

- **Tailwind-утилиты в `shared/ui`** (`scroll-area`, `page-title`) — легаси-мост, новый код на CSS Modules. Не расширять, при случае перевести на токены.
