# Дорожная карта проекта: D&D инструмент для русскоязычного сообщества

**Версия:** 0.1 (черновик)  
**Дата:** 2026-11-05  
**Цель:** Создать удобный специализированный инструмент для мастеров и игроков D&D (заметки, лор, персонажи, предметы, заклинания) + сообщество для обмена контентом. Монетизация через подписки (хранилище) и косметику (темы/рамки).

---

## 1. Видение продукта

- Ядро: система хранения и организации информации по кампаниям (аналог Notion/Obsidian, но заточенный под D&D).
- Сообщество: общий пул кампаний, NPC, предметов, кастомных заклинаний.
- Кастомизация: своя UI-библиотека с переключаемыми стилями (готика, ар-деко, ар-нуво и т.д.).
- Монетизация: freemium (лимит хранилища) + подписка + донаты/косметика.

---

## 2. Технический стек

### Frontend
- React + TypeScript
- CSS Modules
- Своя UI-библиотека компонентов (с поддержкой тем и декоративных рамок)
- React Query — работа с данными
- Zustand — глобальное состояние
- React Hook Form + Zod — формы и валидация

### Backend (рекомендация на старте)
- **Supabase** (Auth + PostgreSQL + Storage + Row Level Security)
- Альтернативы: PocketBase или Firebase
- Самописный бэкенд — только после появления пользователей и понимания ограничений

### Платежи (позже)
- ЮKassa / CloudPayments (для РФ)

## 4. Ключевые риски и митигация

| Риск | Митигация |
|------|-----------|
| Слишком широкий scope | Жёстко держаться фаз. Не добавлять фичи раньше времени |
| Модерация контента | Видимость + жалобы с самого начала публичного шаринга |
| Проблемы с авторскими правами (WotC) | Чёткие правила: только свой контент / homebrew |
| Хранение файлов | Лимиты с первого дня |
| Сложность бэкенда | Начинать с Supabase, не писать свой сервер сразу |
| Платежи в РФ | Заранее изучить ЮKassa |

---

## 5. Монетизация (черновик)

- **Бесплатно:** полный базовый функционал + ограниченное хранилище (например, 150–200 МБ)
- **Подписка:** увеличенное хранилище + приоритет
- **Косметика / донаты:** новые темы, рамки, анимированные элементы интерфейса

Важно: ключевые фичи (поиск, базовый шаринг, экспорт) не прятать за пейволлом.

---

## 6. Ближайшие конкретные шаги

1. Нарисовать data model (Campaign, Note, Character, Item, Spell, User + связи и видимость).
2. Поднять проект в Supabase и сделать авторизацию.
3. Реализовать одну сущность end-to-end (например, Campaign + Notes).
4. Сделать 1–2 декоративные рамки в UI-библиотеке и проверить переключение тем.
5. Показать сырой прототип 5–10 людям из сообщества и собрать фидбек.
